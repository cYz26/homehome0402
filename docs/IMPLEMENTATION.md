## CI 验证预算修订 · 2026-09-15

用户反馈 GitHub Actions 发布被浏览器检查阻断：三个长流程分别在不同步骤耗尽 90 秒总时限。CI 单流程预算调整为 300 秒，同时为单次操作、导航和下载请求设置独立时限；保留完整画质、像素回归、断言及失败证据。此调整属于验证基础设施，不改变建筑或展示版本。诊断依据及验证边界见 [QA](QA.md#github-actions-浏览器总超时修正--2026-09-15)。

后续仍有主卫细节点击超时，已在两核 Linux / SwiftShader 上完成同一失败流程的修正前后对照。静态画质用例将绘制完成与点击同步分开，使用减少动态效果设置及明确的 GPU 完成等待；一般交互测试和实际网站保留原有动画、画质。详见 [QA 对照记录](QA.md#ci-主卫点击与绘制同步修正--2026-09-15)。

## CI 模型加载阶段与 Action 运行时修正 · 2026-09-15

最新提交 `2e93db7` 的远程流程为 7 / 8 通过，失败点移至高清模型加载后的 20 秒占位图断言；既有 120 秒绘制等待位于该断言之后，未覆盖下载、解析和首帧。模型加载统一使用有名称的 120 秒阶段预算，覆盖首次进入、分享恢复、重试和高清切换；普通断言、点击、单项测试及套件的原有预算保留。高清用例对真实资源增加 25 秒受控响应延迟，持续覆盖成功加载超过普通断言预算的情况。

同时更新验证与部署作业中的官方 Actions，并检查 Pages 上传 Action 的嵌套依赖，均声明采用 Node.js 24 运行时；项目构建仍使用 `node-version: '22'`。本次只调整验证与发布基础设施，建筑资源及用户已确认的展示版本保持原发布清单。对照数据、官方版本依据和远程待验状态见 [QA](QA.md#ci-模型加载等待与-action-运行时修正--2026-09-15)。

## CI 分片与构建复用 · 2026-09-15

用户要求缩短发布等待时间，明确采用两个独立 runner 按用例分片、每个单 worker，并复用已验证的构建。工作流现为 `build → browser[1/2, 2/2] → verify → deploy`；通过 `fullyParallel` 启用用例粒度分片，全部 8 项测试、高清响应延迟回归、标准画质、AO、阴影及剖切像素检查继续执行。

构建阶段保留图片脱敏、模型、行为与发布检查，只生成一次 `dist`。浏览器分片按同一 artifact ID 下载构建，剖切夹具读取该构建中的资源；合并阶段核对完整测试清单、单次通过结果及附件，证据绑定测试清单和构建 artifact ID。仅所有检查成功后发布同一份 Pages 产物，部署阶段不再重复安装、检查和构建。新增的下载 Action 使用 Node.js 24；项目构建继续使用 Node.js 22。

操作入口见 [README](../README.md#发布与验收)，本地分片、报告合并、失败守卫及线上待验边界见 [QA](QA.md#ci-分片与构建复用--2026-09-15)。本次调整验证流程，不生成新的建筑或展示资源版本。

## 网页模型加载优化 · 2026-09-15

用户反馈打开网页后模型加载长时间停在百分比提示。实测线上首次进入约 97.2 秒，模型下载约 86.5 秒；主要瓶颈为大文件传输，另有查看器代码到模型的串行等待及被预览覆盖的空场景绘制。

已实现模型与代码/导航并行加载、64 KiB Range 探测后四路分段下载、完整文件 SHA-256 校验及按哈希复用浏览器模型缓存；取消覆盖所有分段和等待中的代码导入。加载提示区分下载、解析和首次绘制。建筑、GLB、纹理与标准画质参数保持当前已验证资源，应用修订为 `2026-09-15-model-loading`；实现边界见[查看器设计](viewer-design.md#模型加载--2026-09-15)。

新增 `release:prepare -- --code-only`，对网页代码变更复用已有资源并刷新源码及交付清单哈希；若建筑或资源生成输入变化则拒绝此入口。性能对照、浏览器检查和发布待验状态见 [QA](QA.md#网页模型加载优化--2026-09-15)。
