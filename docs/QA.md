# v06 交付核对

本轮在 macOS 上核对 metric-v06，迁移基线为 metric-v05。当前源模型、原始 GLB、压缩模型、空间数据、导航、平面图及渲染通过同一发布清单关联。用户视觉确认与真实手机帧率分别记录，技术检查不代替这两项验收。

## 模型、数据和门向

- 源模型 / 独立重导入均为 **690 个部件、42,000 个三角形**，无退化三角形；最大边界差约 **0.000000954 m**。
- **19 / 19** 项原有尺寸、洞口、空置区域、窗户、厨房、推拉门、连续宽槽及保留要求通过。
- **73 个稳定逻辑构件**覆盖全部部件；**11 个空间**含入口、走廊与凹位，面积按实际多边形扣墙计算，标为模型估算。
- 与 v05 比较，所有非门部件的边界和三角形数保持一致。四处平开门保留原洞口，全开位置为：西北向北靠东墙、主卧向西靠北墙、东南向东靠北墙、入户向东外开。
- `model:build -- --verify-existing` 已在内存中重建当前规格，690 部件全部与已验证模型一致；该检查保留现有源文件，不写入新的 Blender 二进制副本。

复杂精装拓扑采用哈希锁定的 v05 模板库，JSON 控制整体位置、尺寸和材质；细部造型更改仍需更新模板。未声称生成了 Blender Assets 插件的封存交付包。

## 资源与发布

- 网页 GLB：**13,360,600 字节，约 12.74 MiB**；7 张 KTX2 纹理、Meshopt 几何、249 个网格，保留全部 73 个构件映射。压缩前后每个构件的边界差小于 1 mm。
- 首屏核心资源约 **0.25 MiB**；将页面所有懒加载图像也计入后，静态资源上限约 **0.58 MiB**，低于 1 MiB 预算。
- 首次可交互资源约 **14.85 MiB**，包含全部 JS、模型、属性、导航和本地解码器，低于按视觉优先调整后的 16 MiB 预算。
- 发布清单选择 31 个资源，总计约 34.23 MiB（含按需高清 GLB）；旧模型继续归档，构建不全量复制 `public`。
- **13 / 13** 项发布检查通过：版本、源码/资源哈希、构件覆盖、几何保留、门向、面积、压缩扩展、图片元数据、预算、无 Three.js 首屏预载、构建资源清单与 SVG 完整性。

精确字节及摘要以 `model/release-checks.json`、`public/release.json` 和 `docs/delivery-record.json` 为准。源码变化后重新生成发布清单；单个机位重新渲染时保留各图片的独立来源记录，拒绝发布与当前模型不匹配的图像。

## 视觉优先修订 · 2026-09-15-section-quality

- 用户报告的条纹来自 SSAO 法线/深度预渲染没有继承主画面的剖切规则；压缩和原始模型均复现。关闭投影阴影不会改变该症状。现已修复每个表面的剖切、深度偏移和透明物体处理，保留 AO 与阴影。
- 同时修复 glTF 按材质拆分同一实体时，竖向剖切轮廓不闭合的问题。
- 标准模式使用原生像素比、32 样本 AO、4× MSAA + SMAA、4096 阴影、1024 镜面及 GPU 支持的最高各向异性过滤；流畅模式为手动选项。
- 7 张纹理保留源图尺寸（1254 → KTX 块对齐 1256），采用 UASTC level 4，不开启 RDO；不再缩小到 768。此压缩仍不是逐像素无损。
- 新增真实 WebGL 像素回归，使用旧 AO 作为必定复现的对照，再验证网页/原始模型的多个缩放倍率和三个剖切方向。13 个新切面截图及像素记录见 `docs/evidence/metric-v06/section-metrics.json`；全部 8 项浏览器流程通过。
- 已在用户原机位的 Codex IAB 页面刷新并实际缩放，红箭头对应的长墙切面均呈平整颜色。真机帧率仍单独待测。

实现依据：[Three.js SSAOPass 源码（r180）](https://github.com/mrdoob/three.js/blob/r180/examples/jsm/postprocessing/SSAOPass.js)、[材质剖切接口](https://threejs.org/docs/pages/Material.html)。发布清单通过 `presentationRevision` 区分本次显示修订，建筑模型仍为 metric-v06。

## GitHub Actions 浏览器总超时修正 · 2026-09-15

用户提供的 Actions 日志显示 5 / 8 通过，桌面、平板和标准 / 高清三个长流程均耗尽单项测试的 90 秒总时限，分别停在分享按钮、下载 HEAD 请求和 750 ms 的机位等待；没有报告断言不匹配。切面像素回归在该次 CI 中通过，用时约 2 分钟。这说明先前 macOS 的通过记录不能作为远程 CI 已通过的依据。

本机以 SwiftShader 软件渲染运行标准 / 高清流程约 45 秒通过，叠加 6 倍 CPU 限速约 51 秒通过，未复现远程超时。远程日志确认了总预算耗尽，但具体 runner 的 GPU 后端和每阶段耗时尚无 trace 证据，不能据此认定网站存在固定按钮故障。

修正测试预算：CI 单流程上限 300 秒（本地普通流程仍为 90 秒，切面流程仍为 180 秒），整个浏览器套件上限 20 分钟；单次 UI 操作 / 导航上限 30 秒，下载 HEAD 请求上限 15 秒，原有断言上限 20 秒保留。Actions 浏览器步骤上限 22 分钟、verify 作业上限 30 分钟，留出失败报告与证据上传时间。保留单 worker、全部断言及失败 trace，不增加自动重试。

本次只修改验证配置，不调整网站标准画质、资源、渲染实现或用户已确认的视觉版本。2026-09-15 在 macOS 执行 `CI=true npm run test:browser`，**8 / 8 通过，总耗时 183.6 秒**，无跳过、重试或 flaky；标准 / 高清流程 47.6 秒，切面像素回归 22.6 秒。报告确认实际使用单流程 300 秒和套件 1200 秒预算。

证据收集器成功提取 33 张图并绑定当前发布清单、构建和测试源码哈希，保存在本机忽略目录 `.asset-work/browser-evidence/metric-v06/`；保留原先入库的用户已确认视觉证据。JS 语法、文档链接和 `git diff --check` 通过。本机无 GitHub CLI 登录态，公开 Actions API 返回 HTTP 403，远程复验和 Pages 部署结果尚未读取；本地 CI 配置运行不代表 GitHub 托管 runner 或真机通过。

## CI 主卫点击与绘制同步修正 · 2026-09-15

后续 Actions 日志为 7 / 8 通过，标准 / 高清流程仍在“双人洗手台”点击的 30 秒操作预算内失败。上一轮扩大总时限只解决了部分问题。

- 仅静态标准 / 高清画质用例模拟系统的减少动态效果设置，关闭机位过渡和自动滚动动画；桌面、平板、手机及触摸流程仍使用原有动态效果。
